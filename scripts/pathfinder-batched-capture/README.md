# Bounded capture qualification

These tools operate only on a managed **owned restore at5191**, never the original
installation or retained5190demo. Supply its exact owner and runtime; ownership,
image/network/SQL identities are checked. No credentials appear in arguments or
receipts. Private SQL rows stay under ignored owner-marked `.scratch/` directories.

`qualify.mjs --runtime <path> --owner <uuid> --compiled-server <own-compiled-root>`
checks five served runtime module hashes, the exact repository/integration-driver
compiled bytes and loopback health. It records the actual Linux runner hash and
engine mode. A matched module is not a new engine/parity/security-suite result.

`integration.mjs` takes the same arguments. It runs the production repository's
matching SQL against temporary fixtures in an outer rollback on the exact new
owned PostgreSQL endpoint. It checks an existing synthetic fixture marker before
creating TEMP tables. It does not write public business tables or prove the full
production FK schema/HTTP/native behavior. Bounded raw output is saved before
assertions, including failures and deadline/transport flags.

`business.mjs --runtime <path> --owner <uuid>` captures a new read-only baseline
for all existing projects, cable types, cables and model selections. Its v2
projection uses explicit string keys and PostgreSQL `to_jsonb(row)::text` strings;
NUMERIC/BIGINT values are never decoded to JavaScript numbers for comparison.
Actual SQL precision controls verify this distinction. It saves full private rows
before assertions and emits only hashes/counts/target metadata.

After the operation, call `business.mjs` with the same arguments plus
`--baseline <compact-receipt-path>`. Existing rows must remain byte-identical and
new rows are refused by default. `--allow-new` is reserved for an explicitly
authorized additive seed; that seed must independently validate its exact new
identities/counts. This four-table proof does not cover derived Path Finder jobs,
artifacts, registry history, auth records or unrelated storage.

The first v1 baseline decoded SQL JSON and cannot establish arbitrary-precision
preservation retrospectively. It was not used as an exact comparison. The later
v2 baseline applies only to operations after its recorded capture time. Preserve
these distinct evidence scopes and all historical failed checks.

# Проверка на записаните пътища

Изпълни от копието на WFC на сървъра, като замени `wfc-api`, ако контейнерът има друго име:

```powershell
Get-Content ./scripts/pathfinder-saved-currentness/audit.mjs -Raw | docker exec -i -w /app wfc-api node --input-type=module - | Set-Content ./saved-currentness-audit.json -Encoding utf8
if ($LASTEXITCODE -ne 0) { throw 'Проверката не завърши. Виж status и error в резултата.' }
```

Не е необходимо ново изграждане или обновяване на контейнера. Проверката чете текущата му изчислителна версия и данните за кабелите от `JB_Prod20_03` в проект `da667921-1f13-4c1d-9f87-063d127b98ce`.

Резултатът показва текущите стойности, последното предложение, последния записан резултат и версиите на изчислителния механизъм. `SAVED_RUNTIME_PROFILE_CHANGED` или `SAVED_ENGINE_IMPLEMENTATION_CHANGED` доказва конкретна промяна, която е достатъчна за отказ на строгата проверка за актуалност. Липсата на такава разлика **не доказва**, че целият път е актуален: останалите зависимости и доказателството за запис също трябва да се проверят.

Данните се четат в потвърдена `READ ONLY` транзакция. Не се променят маршрути, локации, дължини или състояния. Изходът не съдържа пароли или адреса за връзка с базата. Лимитите са 100 кабела, 10 секунди на заявка и 30 секунди общо; по-дългите полета за маршрут се ограничават до 4096 знака.

За друг проект или табло добави аргументите след `-`, например:

```powershell
Get-Content ./scripts/pathfinder-saved-currentness/audit.mjs -Raw | docker exec -i -w /app wfc-api node --input-type=module - PROJECT_UUID PANEL_NAME
```

## Implemented behavior

The [operator runbook](10-operations-backup-restore.md) and [portable deployment guide](../PORTABLE-DEPLOYMENT.md) describe the executable commands. The WFC backup uses the discovered application, PostgreSQL, MinIO and staging mounts. It stops all declared writers with a 45-second allowance, terminates remaining connections to the exact application database, verifies the fence, and stops MinIO before database/storage capture. A forced worker is reported as forced. Source services must return to their original running/stopped states before a complete backup is published. Failure leaves an incomplete result and runs the same source-resume procedure.

The versioned manifest binds the custom database dump, every actual MinIO and staging file, full business/registry inventories, exact runtime/image IDs and platforms, source inventory including untracked files, and four portable operator modules. The separate operator configuration is protected and is not public evidence or a Git input. Restore needs neither the source checkout nor an internet installation. The delivered five image archives use IDs without mutable repository tags.

Restore accepts a new owned directory/project/port/volumes only. DB/storage return into private quarantine. Full canonical business and registry rows, reports, aliases, provenance and selection must match. Restored resource sessions and login bindings receive durable revocation; a new target-only JWT secret rejects source tokens. Every ready model resource is read through the existing raw SHA/size verifier before API/web starts. The web service alone joins the front network; DB, storage and API remain on the internal network. Both the actual loopback binding and host HTTP health are checked before declaring ready.

Model audit is an explicit operator command, separate from process health. Missing or corrupt bytes make the diagnostic model unavailable and prevent exposure. A transient storage outage does not rewrite healthy metadata as corrupt. Recovery reuses the existing owner-bounded unpublished importer; published, orphaned and unproven resources are retained. The retention default is a dry-run report with no automatic deletion deadline.

The independent Preparer keeps its existing launchers, image and core. Its new separate operations CLI captures all three persistent roots, all ledger namespaces/WAL/heads/checkpoints, the private signing key and referenced external inputs. Remaining unsafe locks, service-owner records or publication mutexes cause the stopped audit to refuse; they are retained for diagnosis, never deleted to manufacture a complete backup. Its delivered bootstrap runs outside the checkout. Restore preserves job identities and historical proof while keeping provider capability closed; it neither renews proof nor resets submission history.

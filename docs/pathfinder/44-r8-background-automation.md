## Implemented source behavior awaiting final acceptance

### Explicit authority for calculation only

The English project control, **Automatically recalculate model revisions**, uses
a persistent project grant rather than retaining a human bearer or inventing a
login. Strict command contracts provide control revisions, exact idempotency,
enable/disable receipts and audit identity. A grant is limited to its project,
active healthy model and the fixed prepare/trace/compare/match-suggest/calculate
operations. It supplies no Review, Apply, binding confirmation, engineering
mapping decision, Details write or drawing-policy permission.

Persistent grant provenance and short execution authority are separate. Current
grant revision, grant epoch, installation epoch and issuer administrator revision
fence the persistent right. Each execution lease pins model version, selection,
content, operation, owner and finite expiry. The owner token is private; its hash
is stored in the database, and scrubbed provenance contains no execution secret.
Demotion/re-promotion cannot revive the old issuer revision. Restore retains the
audit but changes the installation epoch and requires explicit reactivation.

The Level A login-bound producer and Level B grant producer share the existing
desired/enrolled generation ledger. They do not create competing state ledgers.
Automatic calculation remains proposal production. A current human administrator
must separately Review and Apply the exact applicable proposal. A completed
grant proposal uses current persistent grant provenance for human review; its old
execution lease is not a permanent expiry date for the proposal.

### Bounded protected preparation and resource access

The managed producer uses a fixed capture-only host/frame and the existing
protected bridge, discovery, staged input, evidence and R3 atomic preparation
contracts. Explicit v2 grant variants preserve the strict historical human v1
contracts. No SDK global or general evaluator becomes a product API.

no human cookie or login token. Lightweight authorization pings avoid loading
the model manifest while retaining current grant, issuer role/revision, model,
selection, content, session, load, lease, installation, expiry and revocation

Requests and bytes are bounded. Resource revocation disables in-memory use before
awaited database cleanup and retains the exact cleanup identity on uncertainty.

The fixed browser helper uses the pinned SDK/browser/module inventory and an
owned container profile: nonroot, network none, read-only root, dropped

host broker relays only the permitted same-origin model resource family. The
helper has no Docker socket, application volumes, unrestricted navigation,
external network, public debugging endpoint or supplied script evaluator.

# Selected route hydration and automatic origin continuity

The H1 regression had two independent causes. Completed calculations were
already present, but the popup could keep the Cable list route while its display
handoff waited. Separately, a valid automatic write history was classified as
unproven after default material initialization.

## Popup result lifecycle

Selected-result reads use the proposal's recorded calculation preferences.
Opening an existing result does not require a local submission acknowledgement
or a valid next-calculation draft. A positive acknowledgement, when present,
must still match. Current model, endpoints, barrier scope, result identity and
job cancellation checks remain required.

The popup publishes the exact calculated route text independently of foreground
Show readiness. The main route field no longer falls back to the stored Cable
list routing; stored values remain in the comparison section. Show still waits
for its checked display payload.

Save/Calculate watchers keep their frozen command preferences when a later draft
changes. Account, model and preparation-generation changes remain fenced.
Receipt-proven completion of the selected automatic write does not require the
remaining sibling cables to finish, and parent completion preserves its checked
Show payload without another verification read.

Read-only display hydration does not approve a manual cable update. Review and
Apply retain their configuration, ownership and authority requirements.

## Historical automatic ownership

Read-only inspection of the real H1 cable found two Path Finder write-history
entries and matching automatic receipts. Its initial receipt's after snapshot
and the next automatic receipt's before snapshot differed only in
`materials_initialized` and `updated_at`. Material synchronization had changed
the default-material flag without changing the route, design length or cable
write revision. A full snapshot equality check consequently rejected the valid
history with `AUTOMATIC_PAIR_ORIGIN_UNPROVEN`.

The historical continuity check now permits default material initialization
(`false` to `true`) and later timestamp maintenance (`true` to `true`) when
customization remains false. The complete key set and every other value must
match, including route, design/install length, logical endpoints, type and cable
write revision. Timestamps use exact microsecond comparisons and must advance
monotonically within the successor's authorization time. Receipt hashes,
recorded history, sealed results and the successor baseline remain required.

Tests include a four-receipt chain with repeated material synchronization and
refusals for manual field/revision/history changes, resets, customization,
unexpected fields and invalid, reversed or out-of-bound timestamps. No existing
receipt, ownership flag or cable value is rewritten to repair the history.

## Aalborg input difference

At diagnosis, the live published barrier head was revision 4, containing only
the floor `GENPRI 1 of VOLMODEL 2956` (`dbid:174115`). It did not contain the
walls from the retained 28-obstacle offline case. With the specified H1 From
point, that floor-only result was 56 m and omitted `/BC175`; the earlier
28-obstacle replay was 58 m and included it. These are different obstacle
inputs. No route code is forced or inserted to make their texts equal. The user
will add/save the walls and perform the live model test.

The native six modules, policies and protected 48-file projection remain
unchanged. Installation evidence and final test counts are recorded separately;
this note alone does not confirm installation or live browser acceptance.
